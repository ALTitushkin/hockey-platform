# Хоккейная аналитика и защита от дублей

## Какие статистические источники пригодны для канала?

### Takeaway
Проверка 31.10.2026: NHL score JSON реально читается; MoneyPuck имеет подходящий публичный каталог выгрузок, но прямой HTTP CSV в этой среде встретил Cloudflare. Natural Stat Trick и Hockey Reference не подтверждены как доступные автоматические источники. Публичный доступ не равен открытой лицензии.

### Cited Findings
- **MoneyPuck**: [официальная страница выгрузок](https://moneypuck.com/data.htm) разрешает некоммерческое использование и эпизодическое журналистское использование с явным указанием MoneyPuck.com; остальные случаи требуют обращения к владельцу. Для сбора данных вне этой страницы требуется предварительное согласование. Это собственные условия, а не найденная CC/ODC-лицензия. Для регулярного монетизируемого канала нельзя автоматически трактовать ad-hoc journalism как разрешение постоянной выгрузки.
- Страница содержит сезонные и поматчевые данные игроков, вратарей, звеньев, команд; shot-data содержит xGoals и обновляется ночью. Это дает материал для собственных объяснений качества бросков, реализации и игры вратарей. [Выгрузки и словарь](https://moneypuck.com/data.htm). Словарь обязателен для единиц измерения; xG разных моделей нельзя считать взаимозаменяемыми.
- [Каталог сезона 2026/27](https://moneypuck.com/moneypuck/playerData/seasonSummary/2026/regular/) индексируется поиском с датой файлов 30.10.2026; [прямой skaters.csv](https://moneypuck.com/moneypuck/playerData/seasonSummary/2026/regular/skaters.csv) в web-инструменте определен как text/csv (инструмент не поддерживает этот формат), но прямой Invoke-WebRequest получил Cloudflare challenge. Успешная загрузка и фактическая схема CSV **не подтверждены**. Обход не предпринимался. Дата обновления на поисковом снимке data.htm отстает от каталога; не использовать сниппет как свежесть данных.
- **NHL API**: [score/now](https://api-web.nhle.com/v1/score/now) реально вернул application/json и перенаправил на [31.10.2026](https://api-web.nhle.com/v1/score/2026-10-31). Поля включают game id, season, gameType, gameState, команды с id, playerId авторов голов и передач, goalsToDate, clock и ссылки на видео. Наблюдались LIVE-матчи: источник пригоден для событий матча, но частота обновления и SLA не установлены.
- Дополнительный [NHL Stats endpoint](https://api.nhle.com/stats/rest/en/skater/summary?limit=1) не прочитан web-инструментом; прямой HTTP вернул 500. Это не доказательство недоступности всех Stats API: этот вариант запроса требует отдельного корректного пилота.
- [Условия NHL, раздел 7](https://www.nhl.com/info/terms-of-service) ограничивают использование контента и допускают исключения по письменному разрешению либо применимому праву. Специальная открытая лицензия API и гарантированное право массовой перепубликации не найдены. Доступность JSON сама по себе их не устанавливает.
- **Natural Stat Trick**: [главная](https://www.naturalstattrick.com/) отклонена web-инструментом по robots.txt. [robots.txt](https://www.naturalstattrick.com/robots.txt) виден только неполно в текстовом представлении; конкретные правила для всех агентов и условия регулярной выгрузки не подтверждены. Не запускать HTML-парсер как готовую интеграцию. Скриншоты/таблицы и CSV не проверены, доступность живых данных не установлена.
- **Hockey Reference / Sports Reference**: [страница покрытия](https://www.hockey-reference.com/about/coverage.html) не прочитана этим инструментом; [политика использования данных](https://www.sports-reference.com/data_use.html) вернула 403. Источник проверен как кандидат для исторического контекста, но автоматическая доступность и лицензия не подтверждены. В рабочий парсинг сейчас не включать.
- Дополнительно проверен официальный [NHL Records](https://records.nhl.com/): HTML читается, статистических таблиц текстовый ответ не содержит. Пробный [skater-records endpoint](https://records.nhl.com/site/api/skater-records?limit=1) вернул 404; этот предполагаемый маршрут не использовать как рабочий API.

### Inferences
- Приоритет пилота: NHL факты + MoneyPuck как отдельный аналитический слой после проверки разрешенного режима и успешной выгрузки. NST и Hockey Reference пока только кандидаты для ручного факт-чека.
- Форматы рубрик: «качество моментов против результата», «вратарь сверх ожиданий», «роль россиянина в большинстве», «серия с учетом уровня соперников». Для каждого числа нужны модель, период, ситуация (5v5/PP/all), знаменатель и минимальная выборка.
- Для API — кэш и редкий polling по расписанию; для ночных CSV — максимум одна успешная загрузка за цикл обновления, ETag/Last-Modified при наличии. При challenge/403 остановка, без прокси, маскировки и обхода.

### Gaps
- Не установлены MoneyPuck playerID и соответствие NHL ID: требуется проверка настоящего файла. Не соединять по одному имени.
- Не найдены подтвержденные лимиты запросов, API SLA и отдельные открытые лицензии NHL/NST/Hockey Reference; частота «ночью» документирована только для MoneyPuck shot-data.

## Как минимально убрать межисточниковые дубли?

### Takeaway
Ниже проект алгоритма, а не описание реализованной возможности. URL/hash ловят технические повторы; сущности, события и версии фактов ловят пересказы и сохраняют важные изменения.

### Cited Findings
- NHL score дает устойчивые game id, team id и playerId, пригодные для ключей событий вместо русских/английских вариантов имени. [Проверенный JSON](https://api-web.nhle.com/v1/score/2026-10-31).

### Inferences
1. Сохранять source, source_story_id, canonical_url, published_at, fetched_at, source_revision и оригинальный текст. canonical_url: нормализовать host, убрать fragment и только известные tracking-параметры (utm/fbclid); сохранять параметры, задающие матч/статью. Источник ID хранить с namespace. Редирект или rel=canonical принимать только из доверенного источника.
2. Нормализованный SHA-256 текста: Unicode NFKC, whitespace, отделение известного шаблонного футера. Не удалять числа, даты, отрицания, статус слуха, денежные суммы. Совпадение URL/ID/hash означает уже полученный документ; изменение hash означает новую версию для сравнения, а не автоматический запрет.
3. Извлекать event_key: отсортированные playerIDs + action + teamIDs/from-to + gameID либо дата/период события. Примеры action: injury, trade, contract, goal, milestone. Статус expected/reported/confirmed/denied держать в версии факта и сравнивать явно. Только совпадение имени игрока или команды не означает дубль.
4. Все источники одного события собирать в кластер с provenance. Если значения и статус прежние — новая ссылка дополняет кластер без нового поста. expected → confirmed, новый срок травмы, сумма/срок контракта, новый участник обмена, опровержение или статистическая коррекция → обновление; существенное изменение пропускать даже при совпадении canonical URL.
5. Отдельно fact_key для аналитики: playerID/teamID + metric_definition/model_version + exact_period_start/end + season/gameType + situation + sample/min_TOI + comparison_scope. Хранить value, denominator, rank и last_published_fact. Вчерашний факт с тем же ключом/значением не публиковать повторно даже при новом тексте или другом источнике.
6. Скользящее «последние 10 матчей» каждый день формально получает новый период, но это не автоматическая новизна: сравнивать с предыдущим published fact той же metric-family. Новая публикация только при заранее заданном пороге изменения/пересечении рекорда/смене лидера или существенном новом объяснении. Пороги определить пилотом; не выдумывать универсальные проценты.
7. Семантическая близость заголовка/пересказа — только сигнал кандидатов, не единственный veto. Не объединять несовместимые числа разных xG-моделей; не смешивать сезон и карьеру, регуляру и плей-офф, all и 5v5. Сомнительное совпадение отправлять на проверку.
8. Разделять received, clustered, selected, pending_delivery, published. Новость считается опубликованной после доставки; дедуп входящих не должен удалять сохраненную ожидающую доставку. Telegram/MAX — отдельные отметки доставки по одному editorial_item_id. При сбое между отправкой и подтверждением требуется reconciliation, иначе exactly-once не гарантируется.

### Gaps
- Код и текущая схема хранилища в этой работе не менялись; это проект, требующий сопоставления с существующим news/stories.py и тестового корпуса.

## Что проверить перед подключением?

### Takeaway
Нужен небольшой пилот доступности, разрешений и редакционной новизны; результаты этого исследования не означают готовый автоматический сбор.

### Cited Findings
- Ограничения автоматизации наиболее явно сформулированы у [MoneyPuck](https://moneypuck.com/data.htm); общие условия NHL доступны на [официальной странице](https://www.nhl.com/info/terms-of-service).

### Inferences
- В пилоте проверить реальные CSV заголовки, идентификаторы и временную метку, единицы и missing values, стабильность схемы, отличия сезона/матча; логировать тип ответа, не принимать HTML challenge за CSV.
- Собрать тестовые пары: одинаковая новость по разным URL; обновление на том же URL; слух → подтверждение; гол с исправленной передачей; разные действия одного игрока; те же xG за тот же период; другое окно при почти неизменном результате; отличие 5v5/PP; новый рекорд; ошибка отправки и повтор. Проверять и подавленные дубли, и ошибочно заглушенные обновления.
- Источники связывать по факту, но для канала выпускать собственное объяснение с ссылкой/атрибуцией, а не перепубликацию чужой таблицы или статьи целиком.

### Gaps
- Пользовательский статус монетизации и письменные разрешения не проверялись. Технический успешный пилот еще не проведен.
