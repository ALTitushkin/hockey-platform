# Регулярный теневой пилот источников

Цель: за7дней измерить дополнительную пользу DFO/AHL и качество сопоставления с NHL, сохранив новые факты.

## Основание и границы

Задача владельца01.11 и предыдущий разовый пилот35 RSS-записей. Свежие пользовательские замечания выявили ошибки серий/карточек, закрытые v0.17.1/2. Метрик очищенного внешнего спроса в этой итерации нет: тестовые прогоны/healthcheck не считаем читателями; scope ведём от продуктовой задачи. Производственные логи/чужие сообщения не очищаем в рамках этой работы.

Ресерч: [DFO robots](https://www.dailyfaceoff.com/robots.txt), [DFO policy](https://www.dailyfaceoff.com/privacy-policy), [AHL terms](https://theahl.com/terms-of-use) проверены01.11. RSS рассматриваем как специально предоставленный канал; это интерпретация для ограниченного внутреннего пилота, а не разрешение на перепубликацию/AI-переработку материалов. Опрос только RSS/robots, без статей/изображений/обхода. Полные тексты не сохраняем и модели не передаём. При запрете/403 источник отключается.

## Scope и исполнение

- P0: отдельный контейнер128MiB/0.15CPU/no-swap, без токенов и доступа к основным черновикам/авторизации; fixedHTTPS hosts/redirects, robots, conditional GET, 15мин, AHL>=10сек между GET к хосту.
- P0: persisted start/end7дней, restart не продлевает эксперимент, завершение без автоперезапуска; ошибки источников изолированы, отчёт остаётся на диске.
- P0: уверенное сопоставление стабильных NHL ID, типа действия и даты эпизода. Разные формулировки одинаковых фактов — duplicate; expected→confirmed/новые сроки/суммы — update; неизвестная полнота — только документный дедуп/кандидат на разбор.
- P1: агрегированный отчёт по источникам, документам, совпадениям событий, новым версиям, ошибкам и задержкам. Недельные выводы доступны после фактического завершения периода.
- P2: автопубликация новых источников и «Неделя наших» — последующие этапы после пилота.

Роли: PM/Dev — основной агент; runtime HTTP/loop — отдельный исполнитель; независимые QA/security — перед принятием ветки. Основной агент отвечает за matcher, compose/deploy, проверку ресурсов и запуск.

## Два эксперимента

1. RSS приносит полезные кандидаты сверх NHL: считаем eligible unmatched/cross-source matches/lead-time; полезность до разметки не утверждаем. Цена: максимум3 основных GET/15мин плюс robots/headers, отдельный небольшой контейнер, 0 LLM-запросов.
2. Правила сущностей/фактов склеивают разные заголовки без потери обновлений: gold-пары, отдельные метрики confident/unclustered, ручной аудит спорных пар по завершении. Оптимизировать процент автоматического подавления до разметки нельзя.

## DoD и риски

Офлайн-тесты deadline/restart/cache/robots/redirect/ошибок и смысловых пар зелёные; QA/security замечания закрыты. CI собирает образ и проверяет импорт. Отдельный сервис реально запущен, start/end/next_poll записаны, первый цикл и повтор/304 проверены, память/CPU/swap/OOM измерены. Основной новостник остаётся исправен. План отката: отключить только shadow-сервис; предыдущий образ доступен штатным Actions news_image=previous.

Риски: неоднозначные фамилии → не склеивать без полного имени/ID; неполные факты → не делать auto-suppress; изменение правил сайта → robots ежедневно/403 stop; падение RSS → backoff без retry storm;7дней ещё не прошли → не объявлять эксперимент успешным/закрытым.
