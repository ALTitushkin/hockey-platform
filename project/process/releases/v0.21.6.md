# Релиз v0.21.6 — восстановление superseded инфоповодов

## Причина

В production 15.11 повторялась ошибка «версия заменена более свежим источником; ревью этой задачи недоступно» для инфоповода Джордана Стаала. Событие оставалось в `pending_items`; на каждом 15-минутном проходе цепочка находила старый superseded-черновик, пыталась доставить его и прекращала обработку до пересборки свежей версии. Та же ранняя остановка в ветке эквивалентного черновика могла повторять попытки бесконечно.

## Изменение

- Перед повторным использованием эквивалентного или существующего черновика проверяется его статус очереди.
- `superseded` считается терминальным статусом этой версии: система не доставляет старую кнопку/задачу и продолжает сборку из актуального источника.
- Успешно переиспользованная эквивалентная задача теперь удаляется из pending-состояния и отмечается seen.
- Публикационный ledger остаётся единственным источником защиты от дублей; новая генерация не означает автоматическую отправку.

## Проверки и границы

- Добавлена регрессия superseded review → свежая версия.
- Полный локальный гейт: 298 unittest, 27 news, 5 delivery, Ruff, валидаторы data/calendar, diff check — зелёные.
- Миграций БД нет. Сохранённые черновики не переписываются и вручную не отправляются.
- Откат: GitHub Actions → CI/CD bot → Run workflow → `news_image=previous` (v0.21.5 image/commit `8d609da910ab7ebf588bcd2151187b7d1671cfcf`).

## Результат выката

Будет заполнен после CI/CD и production healthcheck.
