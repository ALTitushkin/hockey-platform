## Что не установлено

Неверную принадлежность игроков в опубликованных утренних/вечерних карточках этим
разбором не объявляем: необходима независимая сверка ID/команды на дату матча с API.
Наличие знакомого игрока в неожиданном клубе само по себе не доказательство ошибки.
Счёт2:5 на league и5:2 в описании победы Pittsburgh — обратный порядок команд, не ошибка счёта.

## Следующий срез исправления

Разделить до рендера готовый публикационный материал и незавершённую редакторскую задачу.
Для неразрешённой личности показывать источник/недостающее поле, не выпускать фиктивную
готовую PNG. На готовом пути один выбранный главный claim управляет заголовком, вводной
и карточкой; fallback не должен обходить этот контракт. Операция и прежний контракт —
разные события, общие числа/имена в источнике не подтверждают их связь в новом предложении.
Не лечить это только blacklist двух фраз или ещё одним общим LLM-прогоном.
Проверки на этих сохранённых случаях должны включать вид PNG, а не только значение spec.

## Исправления локального кандидата14.11

- Если typed-пакет не распознал событие, pipeline теперь не вызывает свободный LLM-пересказ
  и не рендерит карту без установленного героя/клуба. Создаётся закрытый от публикации
  редакторский draft: исходный заголовок, краткая причина и прямая ссылка на страницу NHL.
- Старый черновик без packet, который ещё не опубликован/не отклонён/не закрыт, не отправляется
  повторно только потому, что он уже есть по тому же ID. При следующей обработке он заменяется
  задачей с источником. Перед заменой проверяется delivery ledger по имени документа;
  `published/sending/uncertain` сохраняют прежний документ. Эквивалентный новый draft также
  не переиспользует старую свободную копию.
- Вводная в «Ночи наших» ограничена игрой главного выбранного игрока; если там нет подходящего
  победившего вратаря, вводная не заимствует игрока из другого матча. Для night highlight и
  вводной теперь общий выбранный сюжет.
- «Не играл прошлый матч» показывается как отдельное наблюдение, не как «Под вопросом».
- В QA добавлены проверки на сохранённый malformed draft без packet: он заменяется source-task
  без generated text/image, если ledger не указывает на доставку; `sending/uncertain` сохраняют
  прежние байты. Полный локальный suite:282 теста, Ruff `news/ tests/` чистый.

Это защитное сужение публикационного пути, не полное решение покрытия новостей: у Кевина Бала
нет локального RU-identity, а тексты об операции и часть подписаний пока не имеют шаблонов.
Они должны оставаться задачами редактора без карточки и отправки в канал, пока не появятся
проверенный ID/клуб и fact-template. Опубликованные посты70/71 не редактировались задним числом.
Эта версия не выкачена; live PNG/доставка и следующая команда релиза остаются отдельным этапом.

## Live-разбор причин непубликации14.11

Read-only SSH за последние72ч плюс сохранённые JSON в `/app/news/out`:

- `NEWS_AUTO_PUBLISH=1`, `NEWS_STORIES_AUTO=1`, контейнер `hockey-news` Up5days. Утренние
  league/night записи проходят автопубликацию (`message_id 81–89`); это не общий отказ бота.
- В32 story-черновиках за12–14.11 нет ни одного `fact_packet`, все `auto=false`,
  `published=[]`. Они доставлялись владельцу на ревью (message_id290–406), канал не вызывался.
  Очередь на момент проверки: `needs_revalidation=21`, `legacy_review=5`, `expired=1`,
  `superseded=77`, `published=83` (последнее число включает разные сценарии/даты).
- Причины старого `event_decision=review` в этих32 файлах: 32 раза дата не отделена от даты статьи,
  26 неоднозначных участника/клуба, 19 многособытийная сводка, 27 несопоставленный фон по
  здоровью игрока, 14 неподдержанное действие. Пример Status Report про Terry содержал его
  дебют, операцию в июне и прошлогодние очки в одном source snapshot. Старый парсер не выбирал
  точное предложение, поэтому модель смешивала контексты; факты затем понижали `auto=false`.
- Если текстовая генерация не проходила гард, одинаковый source часто повторялся каждые15–30мин.
  У части story draft были `issues=[]`, но lifecycle всё равно ставил `needs_revalidation`: без
  packet нет доказанного срока актуальности; в UI нет действия «отредактировать/собрать текст»,
  остаются обновление/закрытие/отклонение. Поэтому owner review не является публикационным путём.

## Локальный fix для отдельного события из Status Report

`fact_packet.report_packet` теперь находит уникального headline-игрока и один клубный раздел,
затем берёт только совпадающую фразу о завершённом дебюте, ожидаемом дебюте или ожидаемом
возвращении. Историческая операция/статистика из следующего предложения не попадает в claim.
На этом контракте автоматически строятся датированная подпись, срок, rubric и PNG; label дебюта
проверен как «ДЕБЮТ», с логотипом ANA. E2E тест проводит selected Status Report debut через process,
ledger, validator и однократный mocked publish. Полный suite290 тестов прошёл в проектной
`.venv` (для Windows temp race использован `news/out/test-tmp`); Ruff и diff-check чистые.

Это покрывает один найденный класс и переводит часть свежих Status Report в корректный авто-путь.
С тех пор добавлены узкие шаблоны для ожидаемого дебюта Фиалы, его активации из IR, ожидаемого возвращения Стаала и точно сформулированной травмы двух игроков в одном матче (Маккиннон/Макар). Для них есть проверки типизации и mocked end-to-end публикации. Операции, подписания без точных условий и события без надёжного NHL ID остаются задачами редактора. Сами сохранённые черновики/прод не менялись; локальный
кандидат не закоммичен/не выкачен. Нужен следующий срез по этим классам и проверка живой ревизии
после отдельной команды на релиз.
