# «Неделя наших в НХЛ»

Статус: ветка `release/weekly-ours-20261102`, кодd6e5cb3; [CI зелёный](https://github.com/ALTitushkin/hockey-platform/actions/runs/41439746515), включая image build/smoke. В прод ещё не выложено.

## Содержание и границы

Выпуск по понедельникам, 12:30МСК (`NEWS_WEEKLY_AT`). Период — предыдущие
понедельник–воскресенье **по датам матчей NHL**, а не по московской дате финальной сирены.
Для выпуска02.11.2026 это26.10–01.11. Регулярный чемпионат; плей-офф пока не включён.
«Наши» берутся из существующего реестра россиян и белорусов, включая его серверные дополнения.

Первые5 полевых по очкам, затем по голам; остальные сыгравшие — в раскрываемом блоке,
включая игроков без очков. Однофамильцы различаются полными именами. Отдельно все
сыгравшие вратари: победы, матчи, общий процент отражённых бросков, сухие матчи.
Процент считается из суммы saves/shotsAgainst за неделю, не средним из матчевых процентов.
Выход без бросков сохраняется без процента; сухой матч при поражении по буллитам допустим.

Текст шаблонный, без модели и оценочных эпитетов. Пока без картинки: полный недельный
список помещается в текстовый пост. Автопубликация первых выпусков выключена независимо
от общего NEWS_AUTO_PUBLISH: черновик получает `data.auto=false`, публикуется штатной
кнопкой владельца. Отказ, опубликованные ID и повторная доставка сохраняются.

## Данные, ошибки и ресурсы

`news/weekly.py`:2 HTTPS-запроса к NHL Stats summary — skater/goalie, isGame=true,
isAggregate=true, limit=-1, gameTypeId=2, точные начало/конец периода.
Ещё1 запрос к воскресному scoreboard перед сборкой: незавершённые матчи требуют повторить
позже, частичная неделя не выдаётся за полную даже после ежедневного дедлайна.

Проверяются полнота total/data, уникальность NHL ID, типы и неотрицательность чисел,
сумма голов/передач, диапазон игр и согласованность вратарских счётчиков. Ошибка одного
источника не создаёт частичный выпуск. Нет русского имени — ошибка, а не тихий пропуск.
Неподтверждённое имя блокирует публикацию через существующий гард.
Пустая неделя не создаёт пост. Невлезший в4096 знаков текст не обрезается молча.
Повторное чтение уже сохранённого черновика не обращается к источнику и модели.

В общий транспорт `nhl.fetch_json` пока не добавлен byte-limit; это наследуемое
ограничение и отдельный пункт технического бэклога, не новая зависимость рубрики.

## Команды и проверка

```powershell
python -m news.run weekly --date 2026-11-02
python -m news.run weekly --date 2026-11-02 --review
python -m news.run publish --date 2026-11-02 --kind weekly --to tg
```

Первая команда только сохраняет локальный черновик. `--review` отправляет его владельцу
через существующего служебного бота; publish — явная публикация. При повторном запуске
используется тот же черновик, его отказ и опубликованные message ID.

## Показатель полезности — дополнение02.11

Показатель полезности: каждая строка полевого, включая раскрываемый
список, содержит `+/− +3`, `+/− -2` или `+/− 0` за ту же неделю. Поле `plusMinus`
берётся из уже запрошенного skater summary: дополнительных HTTP/LLM нет.
Принимается только integer, отрицательные значения допустимы. Отсутствие/невалидный
тип в свежем API блокируют сборку; для старых сохранённых данных без поля выводится н/д.
У вратарей показателя нет. В реальном выпуске43 значения, у Кучерова +3 сверено с суммой
game-log. Предпросмотр2220 знаков. 184 проверки новостника и QA зелёные.

## Достижения со ссылками — дополнение02.11

Перед статистикой добавлен блок «Достижения недели». Ссылка встроена в само событие:
`<b>Кирилл Капризов</b> — <a href="https://t.me/hockey_culture/41">500-е очко в НХЛ</a>`.
Отдельных URL или строки «Подробнее» нет. Текст достижения экранируется, адрес строится
только из валидного канала и положительного ID опубликованного сообщения.

Источник — максимум14 локальных дневных черновиков за7 дат матчей (+1 к дате московского
поста). Новые night/league сохраняют NHL ID, дату матча и видимые в подписи достижения.
Старые night читаются только по известным шаблонам строк; старые league без NHL ID
не разбираются из-за риска иностранного однофамильца. Проза модели, анонсы, инфоповоды
и будущие достижения не становятся фактами недели. Неопубликованное, rejected,
deleted_messages, ошибки гарда, другой известный канал и неразбираемые записи исключаются.
Для старого архива без channels предполагается текущий единственный новостной канал;
новые успешные публикации сохраняют channels.tg.

Одинаковое достижение игрока включается один раз, предпочтение — «Ночи наших».
Для многократного одинакового события даётся одна представительская ссылка, это
не новый счётчик достижений. Максимум5 строк по значимости; если событий нет, блока нет.
Новые исторические рекорды по недельной сумме не выводятся. Наличие события в архиве
не заменяет ретроспективный факт-чек исходного поста.

Гард проверяет видимый текст: ID сообщений в href не принимаются за статистику игрока.
Пересборка сохраняет привязку канала, отказ и аудит удаления. Повреждённый optional-архив
не останавливает недельный выпуск; файл более128KiB пропускается.
20 новых unit/интеграционных проверок, полный прогон150 unittest+26news+5delivery, Ruff чист.
QA/security замечания о сохранности удаления и malformed nested fields исправлены.

Реальный архив:14 постов за26.10–01.11,2 события (Капризов/Кочетков), оба со ссылкой
на№41; предпросмотр обновлён,1867 видимых знаков. Локальный микрозамер чтения архива
и render:11.62мс/цикл, peak Python allocations153.7KiB. Дополнительной сети/LLM нет.
