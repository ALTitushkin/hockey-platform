## Грабли (проверено болью)
- **PTB запинен `<22`** — версия 22.x ломает `run_polling` (процесс стартует и тихо выходит). Не обновлять.
- **После деплоя проверять `journalctl`** на строку «Бот запущен …», а не только `is-active` (был кейс обрезанного `bot.py` без `main()` — `py_compile` это не ловит).
- **`.env`:** нужна строка `BOT_TOKEN=...` целиком, голый токен не парсится.
- **AdGuard** с фильтрацией HTTPS подменяет сертификат Telegram → `CERTIFICATE_VERIFY_FAILED`. Решение: AdGuard → Сеть → Фильтруемые приложения → отключить для `python.exe`.
- **`.git`-локи на подключённом диске (Cowork):** коммиты из песочницы падают на `HEAD.lock`/`index.lock` (нет прав на `.git`). Договорённость: PM готовит файлы, **коммитит пользователь** на своей стороне. В PowerShell `&&` не работает — команды по одной или через `;`.
- **Модуль календаря — `bot/calendar_feature.py`** (не `calendar.py`), чтобы не конфликтовать со стандартной библиотекой Python.
- **Поиск:** нечёткое совпадение включать только при пустых exact/prefix — иначе «нмхл» тащит «нхл».
- **🔴 DNS на личном VPS не переживает перезагрузку.** 01.08.2026 в 19:48 сервер ребутнулся — и бот замолчал на два дня: `httpx.ConnectError: [Errno -3] Temporary failure in name resolution` на `get_me()` при старте, systemd поднимал его каждые 10 секунд по кругу (`activating (auto-restart)`). Причина: `/etc/resolv.conf` — симлинк на `/run/resolvconf/resolv.conf`, который генерится при загрузке; в источниках `resolvconf` (`resolv.conf.d/base`, `head`, `tail`) не было ни одного `nameserver`, а ни один интерфейс DNS не отдал → файл сгенерился пустым. До ребута конфиг жил с апреля на том, что раздал интерфейс при установке. **Лечение:** `printf '\nnameserver 1.1.1.1\nnameserver 8.8.8.8\n' >> /etc/resolvconf/resolv.conf.d/head && resolvconf -u`. **Правило: не править `/etc/resolv.conf` напрямую** — там симлинк, правки затрутся при следующем `resolvconf -u`. **Урок шире грабли:** конфиг сервера, которого нет в репо, существует только до первой перезагрузки.
- **Маршруты целы ≠ сеть работает.** При диагностике «нет связи» пинговать и IP (`ping 8.8.8.8`), и имя (`ping api.telegram.org`): первое идёт, второе нет → это DNS, а не сеть и не провайдер. `wg show` на этом сервере молчит не из-за поломки — там AmneziaWG (`awg0`), у него своя утилита `awg`.
- **🔴 `basicConfig(level=INFO)` роняет секреты в лог.** Глобальный INFO включается для ВСЕХ библиотек, включая HTTP-клиенты. `httpx` (внутри python-telegram-bot) на INFO печатает полный URL запроса, а токен бота — часть URL Telegram API. Итог: токен светился в `journalctl` в каждой строке каждые 10 секунд (найдено 19.07.2026, токен отозван через BotFather). **Правило: сторонние логгеры глушить явно** — `logging.getLogger("httpx").setLevel(logging.WARNING)` (и `httpcore`). Проверять по факту: `journalctl -u <сервис> -n 30 --no-pager` и глазами искать секреты, а не полагаться на код.

## Ритуал: разбор логов — обязательная часть КАЖДОГО спринта
В начале спринта (до новых задач):
1. На VPS: `cat /opt/hockey-platform/bot/queries.log` и `cat /opt/hockey-platform/bot/missing_queries.log` → вставить в чат.
2. Разобрать miss-запросы: что искали, почему не нашли.
3. Добавить/улучшить термины по спросу (`tools/add_term.py`), не-словарные запросы → в контент/бэклог.
4. Очистить: `> /opt/hockey-platform/bot/queries.log && > /opt/hockey-platform/bot/missing_queries.log`

## Процесс главы истории
1. Исследователь → полный markdown-черновик → `docs/history/drafts/ИМЯ.md` (сдавать ПОЛНЫЙ текст, не резюме).
2. PM → QA (канон `docs/history/INDEX.md`, RU-качество, границы между главами, помечено ли спорное).
3. Дев (Cowork) → вёрстка `docs/history/ИМЯ.html` по конвейеру `python tools/build_chapter.py <id>` (мета — во frontmatter черновика; скрипт сам ставит `published:true`+url+summary+sections+keywords в оба `history.json`, Article+Breadcrumb JSON-LD с ISO-датами +03:00 и перешивает навигацию между главами) → `build_seo.py` (sitemap) → пуш.
4. PM → приёмка на проде (страница, якоря, индекс, Article, sitemap).

## Новостник «Культура хоккея» (news/, ветка news/mvp) — уроки 25.10.2026
- «Главное» по очкам пропускает настоящие новости: в первую же ночь шаблон не заметил рекорд Кучерова (1138 очков, лучший бомбардир Тампы) и первые голы Симашева. Теперь события ищет `news/events.py` (рекорд клуба через stats API `franchiseId`, юбилеи, первый гол, победный). Порог рекорда для молодых франшиз обязателен.
- Карьерные события считаем только если в профиле игрока уже учтён этот матч (`last5Games[0].gameId`), иначе выйдет ложный «первый гол».
- Пост сливается, если ради лимита в 1024 знака убрать пустые строки. Сокращать нужно содержание, а не воздух. Правила оформления — скилл `tg-post-style`.
- Кастомные эмодзи в канале боту недоступны без Fragment-юзернейма (Bot API). Premium владельца в каналах не помогает.
- Логотипы клубов хранятся в `news/assets/logos` (`python -m news.logos`), рендер SVG→PNG нужен только при обновлении. Фото игроков не берём.
- Секреты новостника — `news/.env` (в .gitignore). Файл создаёт дев, владелец вписывает значения — не наоборот.
- **Деплой новостника — по стандарту «Инфра и масштабирование»** (сначала я сделал `up --build` на сервере, как у бота, — владелец поправил): образ собирает CI и кладёт в GHCR `ghcr.io/altitushkin/hockey-news:<sha>`, сервер только тянет его. На сервере теги `latest` + `previous`, откат — `workflow_dispatch` с `news_image=previous`, без сборки. Контейнер `read_only`, `cap_drop: ALL`, `no-new-privileges`, `$HOME` в tmpfs. Выключатель — наличие `news/.env` на сервере.
- **Замер памяти app-VPS перед выкатом (25.10.2026):** RAM 3889 МБ, `available` 2028 МБ; сумма лимитов 2816 МБ + новостник 384 МБ = 3200 МБ — укладывается в RAM − 0.5 ГБ (3389), но запас ~0.7 ГБ: следующий сервис уже требует апгрейда. Попутно: у `prizedrawing-*` `memswap_limit` вдвое больше `mem_limit` — нарушение стандарта, но PrizeDrawing заморожен до R1, не трогаем.
- **Обрыв сети при long polling ронял сервис** (`TimeoutError` из `ssl.read` не ловился — ловили только `HTTPError`). Теперь любой `OSError` → ответ `ok: false`, цикл продолжается.
- **GigaChat (25.10.2026):** работает с корнем Минцифры (`news/assets/certs`), 13/14 по гарду, но путает факты — в цепочку сервера не ставим. «Прошёл гард» ≠ «правда».
- **Имена всей лиги — из Wikidata, не транслитом.** «Ночь в НХЛ» пишет о любых игроках, а реестр — только наши. Русские имена берём из Wikidata по «NHL.com player ID» (P3522): `python -m news.run sync-names` → `news/data/names_ru.json` (CC0). Метки ru.wikipedia в трёх форматах («Кучеров, Никита Игоревич (хоккеист)», «Имя Отчество Фамилия», «Фамилия Имя Отчество»), разбор — `names.parse_label`, с тестами. Покрытие на 25.10: все 60 лучших бомбардиров, 319 из 456 игроков ночи. Нет имени — игрока в посте нет.
- **HockeyTech: страна в месте рождения часто пустая** («Kukmor,»). Фильтр по стране насчитал в PWHL одну россиянку, владелец по памяти назвал больше — их пять. Реестр «наших» по низшим лигам — по стране + городу рождения + подтверждение владельцем.
- **Python-правки через heredoc с `\` ломаются** (тот же урок, что в памяти): скрипт упал на синтаксисе ещё до записи, файлы целы. Многострочные правки с `\n` — только через Edit.
- **Смена формата состояния при выкате (25.10.2026).** Я переписал `service_state.json` на сервере в новый формат (по рубрикам), пока работал старый контейнер. Старый код не нашёл `built`, пересобрал «Ночь наших» и вернул старую запись. Новый контейнер прочитал её, решил, что «Ночь в НХЛ» не собрана, и до публикации оставались минуты — контейнер остановлен, состояние поправлено. Дубль в канал не ушёл (защита по `published`), но владелец получил ложное «вышло автоматически». Правило: состояние нового формата пишем **после** замены контейнера (стоп → запись → старт), а новый код читает старый формат. Отчёт владельцу при повторе даты больше не шлётся.
- **«Наши в составах» — не из статистики сезона (25.10.2026).** Первая «Сегодня ночью» брала клуб из статистики сезона и поставила в пост Романова, Демидова и Наместникова, хотя все они на травме (заметил владелец). Теперь игрок в посте, только если сыграл в прошлом матче клуба (бокс-скор НХЛ) и его нет в списке травм ESPN (`news/injuries.py`). Пост в канале заменён через `editMessageMedia` до первого матча.
- **«Сегодня ночью»: картинка и текст не дублируют друг друга (25.10.2026, замечание владельца).** На афише — расписание и наши в составах, в подписи — интриги вечера (`news/intrigue.py`: юбилеи карьеры, серии, темп сезона, серии клубов из таблицы) и кто не сыграет: травма — «не сыграют», не было в прошлом матче — «под вопросом» (не пропадают из поста). Дорогие запросы (составы прошлых матчей, `landing` игроков, таблица) — один раз при сборке, в черновик; перепроверка раз в 30 мин — один запрос к ESPN, пост правится только при изменении. Гард ищет фамилию в именительном падеже — интриги пишем «**Капризов** — 2 гола до 250», а не «Капризову».
- **Уровни в чате обсуждений (25.10.2026, `news/levels.py`).** Тег участника (`setChatMemberTag`, Bot API 9.5) — до 16 символов и **без эмодзи**: «Просмотровый лагерь» не влезает (0 баллов = без тега), эмодзи — только в поздравлении. Работает только для обычных участников, админам и владельцу тег не ставится. Реакции (`message_reaction`) не приходят без явного `allowed_updates`, а в событии нет автора сообщения — автора бот помнит сам (последние 5000 сообщений, в памяти). Хранится только user_id → баллы.

## «Родителям» и работа над ошибками сессии 25.10.2026

- **Публикация до ревью эксперта — блоки `<!-- hold:doctor -->`** (решение владельца, вариант Б): сборка их вырезает, превью показывает. Снять — убрать пометку и `python tools/build_parents.py`. Паттерн — vault «Экспертный-контент-с-ревью».
- **Цитаты — по оригиналу.** WebFetch и поиск пересказывают; фразы ФХР подтверждены скачанным текстом страницы. Источник, сверенный только по аннотации, так и помечаем.
- **Поиск по русскому тексту ловит падежи только по основам слов** («хоккейную школу» не нашлась по точной фразе). Логика одна в `bot/search.py` и `docs/index.html`, тест — на живых фразах обоих.
- **JSON правим точечно.** `json.dump` переформатировал весь `parents.json` (600 строк диффа вместо 15) — откатил, правка через Edit.
- **Мои повторные ошибки:** heredoc с `\w`/`\n` в Python-правках опять дал предупреждения (результат был верный, но правило «backslash — только через Edit» нарушено дважды за сессию). В черновике правил чата забыл «Легенду» — владелец заметил.
- **Сторож (25.10, вечер):** токен служебного бота нельзя ни вставлять в чат, ни вводить через `!`-команду — она тоже попадает в транскрипт. Только свой отдельный терминал. Heredoc-правка с `\n` нарушена в третий раз (`printf` в README превратился в переносы) — для любого текста с backslash только Edit, без исключений.
- **Инфоповоды (26.10):** тег `transactions` в ленте NHL.com неполный (подписание Раймера без него) — читаем общую ленту и классифицируем заголовок сами. Пресс-релиз клуба выходит раньше и без тега игрока, текст NHL.com — через 20–30 минут и с контекстом (травма Шестёркина) — поэтому релиз ждёт час. Ловушки отбора: «Staking His Claim» ≠ вейверы, колонки `*-insider` — мнения. NHL.com пишет числа до десяти словами — гард разрешает их цифрами. Heredoc с `\n` — в четвёртый раз за сессию (`notify(f"…\n…")`); правило только Edit.
