# Теневой пилот источников и дедуп

01.11.2026, ветка `release/source-dedup-20261101`. Эта возможность изолирована от публикации и текущего `stories_state.json`.

## Что работает

- `news/source_shadow.py`: RSS2 DFO/AHL, GUID/link, полный content:encoded или description; предел 2MiB/100 записей. Вложения и внешние статьи не загружаются. DTD/entities и UTF16 отвергаются до XML-разбора.
- `news/source_dedup.py`: source+ID, канонический URL (удаляются только известные tracking-параметры), SHA256 нормализованного текста. Числа, отрицания, содержательные query-параметры сохраняются. История URL не теряется при смене GUID.
- Совпадение текста разных документов действует только в пределах72часов, чтобы независимое событие через недели не подавлялось навсегда. Часы SQLite ledger можно подменять в тестах.
- Событийный контракт `Event`: стабильные NHL ID участников, действие, ID/дата эпизода и факты. Разная формулировка одинаковых фактов — дубль; expected→confirmed, новый срок/сумма — update; новое действие/эпизод — new. Опровержение/исправление старой версии включает явный `revision` в facts.
- SQLite сохраняет все версии/происхождение в одной транзакции. `observe` не означает `published`; Telegram/MAX и доставка этим модулем не затрагиваются.

Повторный прогон тех же файлов:25/25 и10/10 duplicate. [Метаданные проверки](releases/source-shadow-2026-11-01.json). Полные RSS остались в игнорируемом `news/out/source-pilot/`, в git их нет.

Офлайн-тесты:18 для дедупа и4 для RSS. Проверены смена URL, новые факты, отрицания, временное окно, перезапуск БД, небезопасные XML/ссылки. QA и security review выполнены; замечания об истории URL и бессрочном текстовом дедупе исправлены.

## Повторить на сохранённом файле

```powershell
python -m news.source_shadow dfo news/out/source-pilot/dfo.xml --db news/out/pilot.sqlite
python -m news.source_shadow ahl news/out/source-pilot/ahl.xml --db news/out/pilot.sqlite
```

Сохраняются хеши и ссылки; копии текстов и промпты не пишутся в ledger. Модель не используется. CLI не имеет сетевого режима.

## Что ещё требуется

Автоматическое извлечение полного Event из свободного текста пока отсутствует. Без него разные пересказы одного события могут остаться разными кандидатами. Неполные/неуверенные факты нельзя использовать для автоматического подавления новостей. Статистические ключи должны включать модель/метрику, сезон, тип матча, ситуацию и период.

В v0.18.0 подготовлен отдельный регулярный пилот; автопубликация новых источников по-прежнему не включена. [План и трактовка условий RSS](../planning/source-pilot-2026-11-01.md). RSS используется как специально предоставленный канал для внутреннего сравнения, статьи/изображения не загружаются и не перепубликуются. DFO policy/robots и AHL terms проверены01.11. Robots проверяется ежедневно и перед каждым redirect,403/запрет отключает источник;429 сохраняет Retry-After до оставшегося срока пилота. Не включены ESPN/THW,403/challenge не обходятся.

## Регулярный пилот v0.18.0

`hockey-shadow`: тот же CI-образ, отдельный профиль `source-shadow`, без env_file/Codex-auth/основных черновиков. Отдельный том `news-shadow-runtime/`,128MiB без swap,0.15CPU,pids64,read_only/cap_drop. Файл `news-shadow-runtime/enabled` включает запуск при CI deploy. Первое состояние фиксирует срок7дней; перезапуск/релиз его не продлевает. Штатный exit0 не перезапускается Docker. При откате на образ без модуля deploy останавливает только пилот, данные сохраняются.

Сбор каждые900сек: NHL metadata40 (без полного текста) как база сравнения, DFO/AHL RSS. ETag/LastModified принимаются после успешного разбора; состояние и лимиты хостов сохраняются атомарно, AHL>=10сек между запросами, включая redirects. Запускать один `serve`; ручной `tick` параллельно ему запрещён. Ошибки RSS отражаются в отчёте и не мешают основному новостнику.

Alias-кэш только из тегов NHL `playerid-*`/title. Конфликты имён блокируются между опросами. В RSS матчится полное имя; фамилия допускается лишь для ID из тегов конкретной NHL-статьи. Ключ эпизода пока использует дату публикации UTC, поэтому переход через UTC-полночь может дать пропущенное совпадение. Для обычных событий извлекаются статус/числа/срок/признаки травмы и хеш свидетельства; неполные факты не схлопываются между разными пересказами. Автоматическое подавление парафраз ограничено короткими штрафами с известными обоими игроками, суммой и нарушением без новых деталей/отрицаний. Всё это применяется только внутри shadow ledger.

`new/duplicate/update`, `identified_events/unclustered/partial_event_versions` — счётчики наблюдений. `documents_seen` — уникальные source+GUID; `cross_source_events` — уникальные связанные кластеры для источника, а не повторные polls. Архив до старта попадает в `initial_backfill`, не в задержки. Полезность новых кандидатов и precision/recall нужно разметить после7дней, до этого процентов улучшения нет.

Просмотреть состояние работающего пилота:

```sh
docker exec hockey-shadow python -m news.shadow_runner report
docker exec hockey-shadow python -m news.shadow_runner health
```

После штатного завершения читать отчёт без запуска сбора:

```sh
docker compose --profile source-shadow run --rm --no-deps shadow python -m news.shadow_runner report
```

Отключить только пилот: `docker compose --profile source-shadow stop shadow`; перед следующей выкладкой выключить маркер enabled. SQLite/JSON не удалять. Недельный вывод пока не готов: сначала должен пройти фактический период.
