# Стабилизация автопубликации08.11

Статус: локальный кандидат в release/editorial-facts-main, без коммитов/push/деплоя.
Прод остаётся v0.21.1. Поручение — восстановить корректную автопубликацию, а не расширять
все возможности целевой архитектуры одновременно. Сценарии N01–N03/N08–N09.

## Изменения

- Типизированный факт left_game: однозначный игрок/клуб, явный день матча, did not return.
  Исторические даты, позднее возвращение и неоднозначность не получают auto.
  Шаблон публикует только доказанный факт, не пересказывает медицинский фон/статистику.
- Status Report: один герой заголовка, одна доказанная клубная секция, отдельные
  expected_debut/season_debut. Прогноз не превращается в состоявшееся возвращение.
  Поддержаны только явные конструкции; это не универсальный разбор каждой секции/новости.
- Текст и CardSpec из того же packet. Перед отправкой проверяются source evidence,
  packet hash, точная подпись, дата/срок, согласованность event revision и PNG hash/spec.
  Авто story без packet прямо запрещено, даже если producer ошибочно выставил auto=true.
  Тот же валидатор используется ручной и автоматической отправкой.
- Для обычных fallback-карточек соперник в пересказе больше не доказывает клуб героя.
  Для новых typed карточек клуб вообще не выводится из слов текста.
- Датированная новость об уходе из матча/полноценной тренировке актуальна до конца
  следующего дня МСК после действия; прогноз — до конца явно ожидаемого дня.
  Это разные окна сценариев, не общий TTL здоровья. Подтверждённый контракт — без нового TTL.
  Новые классы/неизвестные даты остаются review, не получают дату статьи как дату действия.
- Технические поля тегов и fetched_at не меняют редакционную версию. Watch помнит
  уже рассмотренные версии A→B→A. Одинаковый snapshot или поддержанные одинаковые claims
  используют прежнюю задачу, даже если изменился фон статьи. Существенный новый факт сохраняется.
- Новая возможность extractor не переодобряет прежний backlog: сохранённый snapshot
  переинтерпретируется только для сравнения; прежние auto=false/решение/квитанции сохраняются.
- Кнопка «Перепроверить»: свежий feed+статья, bounded fetch2×5с/одна попытка, локальный кэш имён,
  повторный разбор/проверка, новая версия той же задачи. Публикации внутри refresh нет.
  Версия проверяется до/после I/O и рендера; ledger sending/uncertain/published блокирует замену.
  PNG уникальная: старый файл не перезаписывается. Дата новой публикационной версии отделена
  от даты исходной задачи и даты действия. Неподдержанный факт остаётся с объяснением в review.
- Логи доставки stories различают канал и редакторскую проверку.

## Границы и включение

Нет нового сервиса/таблиц/массовой миграции. Старые JSON/receipts не пересобирались.
Большая чистка slop не выполнялась: общий restore(snapshot) и общий pre-send validator
устраняют дубли на затронутом пути; новая архитектура целиком не внедрялась.

Refresh поддерживает один polling-процесс. Параллельные CLI-записи той же задачи не
поддержаны транзакционным CAS; после отказа может остаться неиспользуемая PNG.
Если статья ушла из feed или факт не типизирован — refresh сообщает ограничение,
не разрешает публикацию. Произвольное редактирование текста/фактов в Telegram пока не добавлено.
Предрендерная спецификация/hash не являются универсальной OCR/семантической проверкой любой
произвольной картинки; рендерный шаблон проверен на фактических PNG этого корпуса.

После отдельной команды релиза: CI/образ → deploy → наблюдение нового полезного auto-цикла
и review/refresh, сверка квитанций/повторов/картинки. При runtime smoke не публиковать старые
черновики для диагностики. Неделю наблюдать долю ready/review/expired и реальные дефекты.
Откат к v0.21.1 сохраняет состояние, но возвращает его ограничения; новые card_spec/hash
поля старый код игнорирует. Совместимость образа проверять релизной процедурой.
