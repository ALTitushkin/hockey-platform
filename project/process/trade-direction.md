# Проверка направления обменов

Статус: в проде с v0.18.2 (02.11.2026, 5d7d6bb); результат выкладки — в `project/handoff/current.md`.

`news/trades.py` без сети и модели разбирает явные английские конструкции
`acquire … from … for …`, `trade … to … for …`, `traded to … by … for …`.
Клубы берутся из словаря NHL, игроки — из NHL ID ссылок самой статьи; фамилия
в заголовке сопоставляется только с этим набором, при неоднозначности разбор не принимается.
Результат: движения `{pid, source, destination}`, исходная фраза, текст компенсации,
причина ручной проверки. Проверяются только заголовок и первое предложение лида,
исторические обмены из последующих абзацев не становятся текущими фактами.

## Что делает новостник

1. Передаёт разобранные направления в существующий запрос редактору; новых вызовов модели нет.
2. Проверяет явные русские «клуб получил/отдал игрока». Противоположное направление
   отклоняется гардом; составные, отрицательные и неподдержанные формулировки требуют проверки.
3. Не допускает автоматическую публикацию при неразобранном лиде, конфликте заголовка
   и лида, неполной компенсации, выборах драфта, дополнительных условиях.
4. Берёт два клуба карточки из конкретного движения игрока. Без разобранного движения
   клубные логотипы не выбираются из общего списка статьи.
5. Сохраняет `data.trade_facts` рядом с `data.auto` в черновике для разбора ошибок.

Это консервативный набор поддержанных конструкций, а не универсальный семантический
валидатор. Корректная, но неподдержанная формулировка тоже может попасть на ручную
проверку. Пики и удержание зарплаты не считаются автоматически проверенными фактами.
Статистический контекст продолжает проверять прежний числовой/именной гард.
Существующие сохранённые черновики не пересобираются: повторная доставка сохраняет
свои ID и не вызывает модель заново. Изменение действует на новые черновики.

## Проверка перед выпуском

Регрессии: `tests/test_trade_direction.py`, `tests/test_trade_direction_qa.py`,
`tests/test_trade_posts_review.py`; карточки и повторная доставка покрыты существующими тестами.
Есть интеграционный сценарий `process → save_draft`: неизвестное направление выключает
`auto` и оставляет объяснение в сохранённых фактах. Все сценарии офлайн, без токенов.

02.11.2026: QA нашёл пропуски составного предложения, отрицания и конфликтующей
компенсации; добавлены регрессии, ошибки исправлены. Полный прогон: 110 unittest,
26 проверок `news.test_news`, 5 проверок доставки; Ruff чистый.

Локальный микрозамер Windows/Python3.14, после прогрева, 1000 циклов extract+check
с tracemalloc: 0.485с, около0.485мс/случай, пик отслеженных Python-аллокаций25.5KiB.
Это не RSS процесса и не замер контейнера на VPS. Сеть и модель в этом цикле не вызываются.
Дополнительные факты немного увеличивают существующий промпт; расходы всего сервиса
и число редакторских повторов этим микрозамером не оценивались.
