## Ближайшая исполнимая задача

Жизненный цикл исторической очереди до расширения авто:

1. Отдельно показывать свежие, legacy, истёкшие, нерелевантные и требующие исправления.
   Историческую запись сохранять с причиной закрытия, без удаления квитанций/источника.
2. Политика срока актуальности по сценарию: ночная сводка, анонс до игры, прогноз возвращения,
   бессрочный подтверждённый факт контракта имеют разные сроки. Не вводить общий TTL для всех.
3. Legacy без доказанного срока/источника не получать auto при миграции. Для кнопки обязательна
   свежая проверка актуальности; осознанная ретроспективная публикация — отдельный сценарий.
4. Ручное исправление и закрытие должны быть доступны через очередь с version-bound решением;
   список /queue не должен заставлять владельца редактировать JSON на сервере.
5. Эти6 случаев использовать как эталон миграции/отбора/истечения/дедупа, затем расширять
   сегментацию Status Report и схемы фактов. Числа auto/review считать отдельно для новых и legacy.

Изменение жизненного цикла пока не реализовано. Прод и существующие решения владельца
этим отчётом не изменены.
